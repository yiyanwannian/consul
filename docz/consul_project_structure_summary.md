## 核心架构总结

### 1. 分层架构设计

```
┌─────────────────────────────────────────┐
│              用户接口层                    │
├─────────────────────────────────────────┤
│  CLI工具    │  HTTP API  │  DNS服务  │  Web UI  │
├─────────────────────────────────────────┤
│              业务逻辑层                    │
├─────────────────────────────────────────┤
│  Agent管理  │  服务发现  │  健康检查  │  配置管理  │
├─────────────────────────────────────────┤
│              核心服务层                    │
├─────────────────────────────────────────┤
│  Consul服务器 │ Consul客户端 │ Service Mesh │
├─────────────────────────────────────────┤
│              数据存储层                    │
├─────────────────────────────────────────┤
│  Raft共识  │  FSM状态机  │  MemDB存储  │  快照管理  │
└─────────────────────────────────────────┘
```

### 2. 模块职责矩阵

| 模块 | 主要职责 | 关键文件 | 依赖关系 |
|------|----------|----------|----------|
| **agent/** | 核心代理程序 | `agent.go`, `http.go` | 依赖所有其他模块 |
| **api/** | 客户端SDK | `api.go`, `catalog.go` | 独立模块，最小依赖 |
| **command/** | CLI工具 | `registry.go` | 依赖 agent 和 api |
| **connect/** | Service Mesh | `service.go`, `tls.go` | 依赖 agent/consul |
| **internal/** | 内部组件 | `controller/`, `resource/` | 被核心模块依赖 |
| **proto/** | 协议定义 | `*.proto` | 被所有模块依赖 |

### 3. 数据流向分析

#### 服务注册流程
```
客户端 → HTTP API → Agent → 本地状态 → 反熵同步 → Consul服务器 → Raft → FSM → MemDB
```

#### 服务发现流程
```
客户端 → DNS/HTTP API → Agent → 本地缓存 → Consul服务器 → MemDB → 返回结果
```

#### 配置管理流程
```
CLI/API → HTTP API → Agent → Consul服务器 → Raft → FSM → 配置存储 → 配置分发
```

## 关键设计模式

### 1. 插件化架构
- **命令行插件**: 通过注册机制支持命令扩展
- **健康检查插件**: 支持多种检查类型
- **CA提供者插件**: 支持多种证书颁发机构

### 2. 事件驱动架构
- **Gossip协议**: 集群成员变更事件
- **状态变更事件**: 服务和健康状态变更
- **配置变更事件**: 动态配置更新

### 3. 分布式系统模式
- **Raft共识**: 确保集群状态一致性
- **反熵同步**: 最终一致性保证
- **分布式锁**: 基于会话的锁机制

### 4. 微服务架构模式
- **API网关**: HTTP API统一入口
- **服务注册中心**: 服务目录管理
- **配置中心**: 集中化配置管理
- **服务网格**: 服务间安全通信

## 性能优化策略

### 1. 缓存策略
```
L1缓存(内存) → L2缓存(本地磁盘) → L3缓存(分布式)
```

### 2. 并发控制
- **读写分离**: 优化查询性能
- **连接池**: 复用网络连接
- **批处理**: 减少网络开销

### 3. 存储优化
- **索引优化**: 多维度索引支持
- **压缩存储**: 减少内存占用
- **快照机制**: 快速恢复和备份
